## Найденные косяки

1. **[Фича-разрыв, главная] У VK Видео и RUTUBE нет переключателя «Видео в движении» вообще.** В настройках только fill/quality/battery/display; UI жёстко fail-closed (`noVideo = parked.moving()`), DESIGN.md прямо фиксирует «There is no video-while-driving switch». У YouTube-приложения переключатель `video_driving` есть с рабочей защёлкой «включается только на стоянке». Три приложения ведут себя по-разному — это и есть задача.
2. **[Согласованность гейта]** В ui/main.js гейт расходится в двух местах: `sync()` (строка ~262) и `pinned()` (строка ~243) вызывают noVideo() независимо; при добавлении защёлки обе точки обязаны использовать одно и то же решение, иначе оверлей и картинка разъедутся.
3. **[Сборка]** tools/build_apps.py (строки 109–110) и tools/test_release.py (115–116) пришиты к точным строкам `Parked.watch(..., { strict: true })` и `const noVideo = () => parked.moving();`. Любое изменение гейта сломает сборку/тесты, если их не обновить — это заметить заранее.
4. **[Небольшое]** У VK/RuTube нет настройки `members`, а ui/main.js (строка 87) фильтрует members-only по `settings.get('members')` → undefined = всегда скрывать. Сейчас безвредно (у VK/RuTube members-флага нет), но при появлении платных видео VK поведение будет немым. Не чиню: поведение корректное, отмечаю.

## Что НЕ является багом (проверено)

- Сервисный прокси YouTube 0.4.5: читает state/proxy.json, раздаёт через stdin/0600, mtime-перечитывание на месте.
- Гонки start/stop/requality: покрыты билетами и ожиданием выхода decoders.
- Исчезновение «0 %» и VK-сообщества: исправления 0.4.5 подтверждены кодом (fail() шлёт state error + error событие).
