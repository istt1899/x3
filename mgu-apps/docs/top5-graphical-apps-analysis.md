# Топ-5 графических MGU-приложений: разбор реализации

Источник: upstream `idrive7-apps` (ветка main, apps/ + kit/). Все пять — эталонные
приложения с canvas-экранами (kind `canvas`), GPU-рендерингом 60 fps через
`mgu-renderd` и автоматическим PNG-fallback. Разобраны кодом, не по скриншотам.

Критерий «топ»: приложения с полноэкранной анимированной графикой из галереи
проекта (M Vitals, eDrive, G-Force, Redline, Drag Timer).

## Общая архитектура (одинакова у всех пяти)

```
app.json  ──kit/tools/build.py──▶  rhmiData (LT_State_Laptimer + graphic-компонент
                                    + bar-кнопки)  +  пакет с kit/runtime
main.js   ──mgu.run({start(ctx)})──▶  ctx.canvas(1600x520) рисует кадр
                                    ui.image('MAIN_GFX', cv) отдаёт его HMI
                                    ctx.loop('MAIN', 10, render)  60 fps GPU / 10 fps PNG
```

- Графика — не PNG-слайдшоу: кадр рисуется в байтовый буфер (`canvas.js`),
  на машине с renderd отправляется как команды рисования (~1 мс GPU),
  без renderd кодируется в PNG (~60 мс, ~10 fps).
- Все статичные части (панели, шкалы, циферблаты) кешируются GPU-слоями
  (`G.layer` / `record.js`) и блитятся (`cv.blit`), живые элементы перерисовываются.
- Взаимодействие: RHMI-bar-кнопки (джойстик + тач), тач-табы страниц
  (`G.frame` пишет `cv.tabRects`, `ctx.onTab`), canvas-кнопки (`G.button` +
  `cv.target`), сеттинги — RHMI-экран с drop-down/checkbox.
- Темы: `ctx.theme()` — M tricolour и др., цветовые зоны виджетов из темы.

## 1. M Vitals (car_vitals, 954 строки) — живые приборы

Четыре вкладки: Engine / Thermal / Fuel / Chassis.

- **Engine**: два радиальных циферблата RPM/boost (`G.radial`), полосы
  мощности/крутящего момента (`G.bar`), скорость readout.
- **Thermal**: `G.stat` с историей 5 минут (`history` → trace под значением),
  полосы температур ОЖ/масла/КПП/амбiente.
- **Fuel & ignition**: давления ТНВД/НТ в `G.bar`, угол зажигания, таблица
  пропусков зажигания по цилиндрам (`G.table`), вычитается UDS/OBD из DME.
- **Chassis**: `G.gmeter` (friction circle), `G.tyres` (давления+температуры),
  разводка xDrive.

Приёмы: вкладки через `G.frame`, кнопка «Next page» в bar, DEMO-бейдж
`[car.data().demo && {text:'DEMO'}]`, сигналы SOME/IP напрямую из app.json
`signals`, UDS-подмодуль отдельным классом (config.dme).

## 2. eDrive (edrive, 1238 строк) — модель важнее виджетов

Приложение-оценщик: «реальный» электрический запас хода считается из обученной
модели (потребление по скоростным диапазонам + климат по полосам температуры,
сиденья/руль отдельно). Данные учатся локально, persist в data/.

Виджеты: `G.ring` (запас хода, заряд), `G.bar` с origin (рекуперация/расход
в обе стороны от нуля), секции куда уходит мощность, журнал зарядок (`G.table`),
ячейки батареи температуры/напряжения.

Приёмы: бизнес-логика (обучение) вынесена в чистые функции, виджеты только
отображают; все выводы подписаны допущениями; климат берётся из
`ClimateMaster.statusClimateSystemOn`.

## 3. G-Force (gforce, 222 строки) — минимальный эталон

Одна страница + Records: friction circle, «конверт сцепления» по 48 секторам,
пиковые значения, все рекорды в `data/gforce_records.json`.

Приёмы (применимы к любому приложению):
- сглаживание сырых сигналов 150 мс скользящим средним перед отображением;
- фильтр физически невозможных выбросов (>3 g отбрасывается как брак сэмпла);
- «тающий» след: точки с альфой по возрасту, каждый второй кадр;
- readout цифр через `G.hold(key, v, ms)` — ограничение частоты перерисовки
  чисел, точка и след остаются на полном fps;
- запись на диск через debounce 5 с + flush на `process.on('exit')`;
- двойное нажатие для разрушительных действий («Delete all» → «Yes, clear»
  с таймаутом 5 с), `G.button(..., {confirm:true})`.

## 4. Redline (redline, 333 строки) — полноэкранная анимация + логика безопасности

G20-стиль: сегментный rev-bar через `G.segBar` (ramp 'hot' к красной зоне),
`G.shiftLights` (12 ламп, строб на отсечке), большая передача `G.gear`,
подсветка SHIFT при достижении точки переключения, оценка каждого переключения
(EARLY/SPOT ON/LATE/LIMITER), журнал переключений.

Ключевой приём — **охранный контур**: пока масло холодное, точка переключения
понижена и ползёт вверх с температурой масла (cold-engine rev guard).
Мерцание через настройку «flash» (фаза blink вычисляется из времени, не блокирует кадр).

## 5. Drag Timer (draggy, 290 строк + timer.js + demo.js) — конечный автомат

Состояния: stop → READY → launch (старт по первому движению или one-foot
rollout) → run (сплиты интерполируются между сэмплами скорости) → end
(подъём газа или все сплиты). Живая трасса скорости (`G.chart`), таблица
сплитов 0-100/¼ mile, лучшие заезды в `data/draggy_runs.json`.

Приёмы: конечный автомат отделён от рисования; demo-модуль отдельным файлом
(та же кривая на стенде без машины); единицы измерения (mph/km/h) через
настройку, пересчёт в одном месте.

## Выводы для наших приложений

1. **Canvas-kind экран обязателен** для любой «графики»: text/menu-экраны —
   только для списков и настроек. app.json: `"kind": "canvas"` + `buttons` bar.
2. Рисовать виджетами kit (`panel/radial/bar/ring/stat/chart/table/pill/
   frame/button`), а не сырыми примитивами, кроме по-настоящему уникальных
   визуализаций (круг силы тяжести рисовали вручную поверх `cv.circle/arc`).
3. Интерактив: tabs через `G.frame` + `ctx.onTab`; действия через RHMI-bar и
   `G.button`; подтверждения двойным нажатием; busy-состояния на кнопках.
4. Плавность: `G.smooth`/`G.hold` для стрелок и цифр; фильтр выбросов;
   полный fps только там, где он заметен глазом.
5. Данные: persist JSON в `ctx.dataDir` с debounce; DEMO-режим без машины с
   бейджем; бизнес-логика отдельно от отрисовки.
6. Безопасность: read-only сигналы; разрушительные действия — confirm + local-only.
