# ТЗ: Bimmer Code 0.2.0 — исправление запуска на X3

## Цель и среда

На BMW X3 с iDrive 7 и установленным MGU Store нажатие плитки должно открывать главный экран Bimmer Code. Владелец подтвердил, что VK/RUTUBE на этой MGU открываются; они служат образцом сборки и жизненного цикла. Версия 0.1.4 впервые показала плитку; 0.1.5 не открыла экран. Целевая прошивка и SDK donor в текущем сеансе непосредственно не исследованы.

## Архитектура

1. Производственный entry — `native/apps/marku_x3_coding/main.js` с `mgu.run({start(ctx)})`. Использовать без изменений runtime и RHMI generator из `media/core/kit`, которые используются рабочими VK/RUTUBE.
2. Удалить из производственного пути собственный subclass OnlineApp, ожидание события `initialized`, ручной runner и source-bundle linker. App Kit сам выполняет `await app.start()`, готовит RHMI и затем вызывает `app.initialized()`.
3. Поставлять npm-layout `package/javascript/app.js`, модули CommonJS и kit/runtime. BMW SDK не включать; Store готовит SDK module из штатного donor на MGU через `preparePackage`.
4. Сохранить ID `marku_x3_coding`, UUID приложения и entry point, чтобы обновление заменило существующую установку. Версия 0.2.0. Сохранять загрузчики RHMI/entry=true, private=false, штатный anchor 20974.
5. Генерировать схемы MAIN/DETAIL и языковые ресурсы из app.json; начальные строки и динамический русский текст проводить через штатные StringBundle/StringId инструменты App Kit.

## Поведение

Главный экран показывает статус диагностики, предупреждение об отсутствии записи, пять функций и навигацию к оставшимся пяти. Выбор функции открывает DETAIL с описанием, ECU, условиями совместимости и статусом. Назад закрывает DETAIL и возвращает к MAIN через штатный стек.

Диагностика запускается только по нажатию. Остаётся один фиксированный запрос UDS `22 F1 50`, source 0xF2, target 0xDF; два allowlist, обработка таймаута, отказа, дублей нажатия и закрытия сохранены. Автоматические запросы, VIN, сохранение идентификаторов, запись ECU, reset и clear DTC отсутствуют. Скорость самостоятельно не проверяется; это указано пользователю. Кодирование десяти настроек не входит в этот выпуск и не должно заявляться работающим.

## Проверки перед выпуском

| Проверка | Требование |
|---|---|
| Прикладная логика | MAIN, две страницы, DETAIL/Back, ручной scan, блокировка повторного scan, русские ошибки, shutdown |
| Жизненный цикл | Запуск реального kit/runtime без события initialized от stub SDK; порядок start → mapping/resources → initialized → open |
| Готовый пакет | Тестировать опубликованный формат, а не только исходники: main=javascript/app.js, нет mgu-app.json и чужого runner |
| Подготовка Store | Настоящий oap_link.preparePackage с синтетическим donor, flat output и SDK module export shape |
| Node 8 | Синтаксис всех прикладных/kit JS, запуск доступных runtime-тестов; отсутствие современного синтаксиса в поставляемых файлах |
| Воспроизводимость | Повторная сборка даёт тот же tgz, локальный каталог соответствует размеру и SHA-256 |
| Поставка | В пакете нет BMW SDK/FA/SVT/NCD/ключей; лицензии уже используемого kit сохраняются |
| Общий каталог | Обновляется только Bimmer Code, остальные компоненты VK/RUTUBE/RideTube сохраняются без изменений |

Синтетический SDK проверяет наш код и упаковку, но не подтверждает конкретный firmware donor и HMI автомобиля.

## Приёмка на автомобиле

После обновления Store показывает 0.2.0. Нажатие плитки открывает MAIN, контроллер и касание выбирают карточку, DETAIL/Back возвращают к списку. Ошибка или отсутствие диагностического канала не мешают открытию меню. Запрос чтения проверяют отдельно на стоянке после успешного открытия UI. До фактической проверки владельцем эти пункты имеют статус NOT TESTED.

## Артефакты

Исходники native app, `tools/build-native.py`, пакет `marku_x3_coding@0.2.0.tgz`, два каталога (USB и GitHub), build-evidence.json с хешами неизменённого kit/runtime, отчёт совета и инструкция повторного аудита. Исходники 0.1.x сохранены для истории; их coding_app.js и prepare.js больше не являются производственным путём.
