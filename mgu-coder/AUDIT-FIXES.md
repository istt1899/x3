# Исправления по аудиту 0.1.0 → 0.1.1

## 0.2.0: замена производственного запуска

По требованию владельца проведён совет: независимо проверены lifecycle/RHMI, пакет Store и доказательность прежних тестов. Результаты — [COUNCIL-AUDIT-0.2.0.md](COUNCIL-AUDIT-0.2.0.md), ТЗ — [REBUILD-SPEC.md](REBUILD-SPEC.md).

Собственный OnlineApp subclass и browserify source bundle заменены обычным module-mode пакетом с тем же App Kit runtime/generator, что у VK/RUTUBE. Производственные файлы теперь в native/apps/marku_x3_coding, старый coding_app.js в сборку не входит. Сохранены ID/UUID, диагностические allowlist и общий каталог других приложений.

Проверены callback UI, распакованный реальный kit/runtime под Node 8 с заглушкой внешнего SDK без события initialized, настоящий preparePackage с синтетическим donor, 33 импорта, 22 JS-файла на Node 8 и воспроизводимость двух сборок. Точная ошибка прежнего SDK на автомобиле и открытие новой версии на машине остаются неподтверждёнными.

## 0.1.5: открытие по нажатию плитки

После 0.1.4 владелец подтвердил появление плитки, но нажатие не открывало экран. В отличие от рабочего App Kit наш обработчик принимал события до окончания инициализации и делал одну попытку openEntryState без повторного mapping/resources. Ошибка только попадала в журнал.

Теперь ранний UUID сохраняется до готовности; после initialized открывается ожидающее нажатие или собственный entry foreground-запуска. Перед открытием повторяются mapping и updateResources. Временные INVALID_UUID/INVALID_COMPONENTID обрабатываются максимум шестью попытками через 800 мс, одновременные нажатия объединяются. Незавершённая загрузка ресурсов ограничена 4 секундами и не блокирует initialized навсегда. Тесты моделируют раннее нажатие, два INVALID_UUID, повторные нажатия и холодный запуск без last UUID. Работа на реальной MGU требует повторной проверки владельца.

Mapping/open также ограничены таймаутом, чтобы не оставлять блокировку opening навсегда. Начальные строки RHMI вынесены в StringId/языковые таблицы, а title сгенерирован без неподтверждённых свойств, как в рабочем App Kit.

## 0.1.4: сравнение с работающими VK/RUTUBE

Сравнены `media/core/kit/tools/build.py`, runtime App Kit и сформированные параметры Bimmer Code. Найдено существенное отличие: `config/base.json` был пустым. App Kit явно включает `rhmiLoadingEnabled` и `entryPointLoadingEnabled`, поскольку некоторые SDK donor отключают эти загрузчики по умолчанию. Описание той же проблемы есть в upstream idrive7-apps issue #39 и комментариях build.py: https://github.com/cauliflowermossgrape/idrive7-apps/blob/main/kit/tools/build.py.

Генератор теперь всегда пишет оба флага true. Параметры entry point приведены к работающему kit: insertionStateId=20974, private=false, defaultLanguage=en_GB. Идентификаторы приложения и UUID сохранены для обновления существующей установки.

startup.test моделирует SDK с обоими выключенными loader defaults; тест реальной линковки проверяет эти флаги в установленном config/base.json выходного архива. Отсутствие rhmiApplication больше не считается успешной инициализацией без плитки. Эти проверки подтверждают исправление конфигурации, но окончательное появление плитки проверяет владелец на MGU.

## 0.1.3: имя Bimmer Code и изоляция ошибок UI

Имя изменено в каталоге Store, RHMI, строковых ресурсах и package metadata; ID приложения остаётся `marku_x3_coding`. На фото подтверждена установка 0.1.2, но плитки нет даже после перезапуска. Без журнала запуска причина на MGU неизвестна.

Исправлен обнаруженный риск: синхронное исключение setValue/setProperty/setEnabled прежде выходило из render и могло прервать setupRhmi до registerEntryPoint. Записи UI теперь ловят оба вида ошибок и кешируют значение только после успешной записи. Компоненты без setEnabled используют свойство Enabled. Новый startup.test.js моделирует фоновый старт, исключение SDK и проверяет регистрацию/ENABLED до initialized. Это mock-проверка, не доказательство появления плитки на MGU.

## 0.1.2: ошибка установки, обнаруженная на MGU

На целевой машине Store остановил сборку 0.1.1: `src/coding_app.js requires "./diagnostics": not an app module`. Линкер сопоставляет буквальное имя `./diagnostics.js`; обычное разрешение Node.js с добавлением расширения здесь не используется. Исправлены все относительные импорты прикладных модулей, включая пример в комментарии, который тоже читает regex линкера.

Добавлен тест, который вызывает настоящий `oap_link.build` со всеми исходниками приложения и синтетическим SDK donor. Он проверяет отказ для старого импорта и успешную линковку исправленной версии. Это не BMW SDK и не подтверждение запуска на MGU.

Название изменено на «Кодировки X3»: разделитель `•` на фотографии отображался вопросительным знаком. Следующая проверка владельца — установка версии 0.1.2, затем запуск интерфейса; native SOME/IP и чтение ECU ещё не подтверждены.

## Изменения 0.1.1

| Пункт | Решение |
|---|---|
| P1-01 | Оставлен открытым: добавление новых отметок авторства исключено по указанию владельца. Существующие лицензии и уведомления сохранены. |
| P2-01 | `npm run build` создаёт отдельный `catalog.github.json` для GitHub и относительный `catalog.json` для USB. `tools/catalog.js` воспроизводит преобразование без сети; `tools/publish-github.js` публикует готовые байты без переписывания URL. |
| P2-02 | Стабильные коды ошибок отделены от технического текста; UI показывает русские сообщения и нейтральный текст при неизвестном коде. Сырая причина доступна только журналу. |
| P2-03 | Принят предложенный аудитором вариант явного ограничения заявления: приложение не проверяет скорость/стоянку самостоятельно. Это указано в UI, README и ТЗ. `Speedlockable` сохранён как декларация HMI; его работа требует проверки на MGU. |

Сигнал скорости нельзя считать проверенным только по наличию похожего интерфейса в чужом проекте. Новые интерфейсы автомобиля и диагностические запросы не добавлены. Для независимой проверки стоянки в будущем потребуются доступный на этой X3 provider, свежее корректное значение и блокировка действия при отсутствии данных.

Новая версия получает отдельный архив и тег `marku_x3_coding@0.1.1`. Архив и версионный тег 0.1.0 сохраняются. Релиз `catalog` служит обновляемым указателем на текущий пакет.

Дополнительно исправлена отмена: закрытие приложения блокирует ещё не отправленный запрос, в том числе внутри отложенной native-очереди. Загрузчик релиза требует чистый Git, сверяет байты архивов с коммитом и проверяет SHA версионного тега; несовпадение прерывает публикацию.

При замене каталога проверка скачивает файл с идентификатором GitHub asset в query-параметре: устаревший кеш редиректа не должен возвращать удалённый каталог и запускать повторную замену. Публикуемые байты каталога при этом не меняются.

Средства сборки и публикации требуют Node.js 18+. Прикладные тесты диагностики и UI дополнительно проверяются на Node 8. Реальная установка, RHMI, native SOME/IP и чтение ECU на автомобиле не проверены. Запись кодировок не реализована.
