# RideTube 0.3.13 — исправление прокси на штатном Node 8

В опубликованной 0.3.12 независимая проверка обнаружила дополнительные ошибки:

- `socket.off()` отсутствует в Node 8 и завершал процесс запроса при ответе прокси. Теперь используется совместимый `removeListener()`.
- HTTPS через собственный туннель формировал `Host: www.youtube.com:80`. Теперь порт и порт по умолчанию заданы как 443; исправлены также запросы миниатюр.
- OAuth device/token отправляются как form fields; запросы InnerTube продолжают использовать JSON.
- Python SOCKS5 сохраняет таймаут на TLS и чтение ответа, чтобы загрузка звука не ждала бесконечно.

Проверено на ПК с настоящим Node 8.17.0 и исходным yt-dlp из пакета: CONNECT/SOCKS5, процесс службы и его stdin, HTTPS Host без ошибочного :80, получение кода входа от YouTube, ответ `authorization_pending` при опросе токена, поиск, JPEG и аудио/видео Range-запросы. Живые запросы использовали локальный аутентифицированный прокси и интернет ПК. Полный Linux-тест демона с Unix-сокетами на этом Windows-ПК не выполнен; отдельные проверки сети, авторизации, прокси, упаковки и интерфейса прошли. VPS владельца и MGU пока не проверены; завершение входа в личную учётную запись не выполнялось.

Обновить оба компонента через MGU Store → Settings → Check now. Если прокси ещё не настроен, один раз создать `/var/opt/jap-ridetube-d/state/proxy.json` с приватным URL, задать 0600 и перезапустить службу. Пароль в каталог и архивы не включён. После обновления проверить вход и воспроизведение на стоянке.

Проверки для разработчика (PowerShell; пути заменить своими):

```powershell
$env:MGU_TEST_NODE = 'C:\tools\node-v8.17.0-win-x64\node.exe'
node native/jap-ridetube-d/test/test_proxy.js
$env:MGU_TEST_YTDLP = 'C:\artifacts\ytdlp.pyz'
python native/jap-ridetube-d/test/test_proxy.py
```

# RideTube 0.3.12 — прокси для сети автомобиля (исправленный выпуск)

Форк [JustAnotherPU/ridetube](https://github.com/JustAnotherPU/ridetube) для iDrive 7. Название и идентификатор приложения сохранены: установка может обновить исходный RideTube.

## Что в версии 0.3.12

Прокси для всего сетевого трафика службы — как задумано в 0.3.11: страница входа TV, поиск и ленты (`youtubei`), токены OAuth, SponsorBlock, миниатюры `i.ytimg.com`, аудио и видео (yt-dlp и параллельные Range-запросы к `googlevideo`). Версия 0.3.11 вышла с ошибками, найденными независимой проверкой опубликованного архива; 0.3.12 их исправляет:

- демон теперь передаёт дочернему процессу URL прокси строкой по stdin, а `--fetch` принимает и строку, и разобранный объект — раньше форматы не совпадали и каждый запрос отвечал `bad proxy`;
- yt-dlp получает URL-строку прокси, а не словарь (словарь давал `TypeError` при запросе);
- `proxy.js` берёт `URL` из модуля `url`, а не из глобального объекта: штатный Node 8 головного устройства его не имеет;
- в `ytfetch.py check` убраны локальные импорты, ломавшие строку прокси (`UnboundLocalError`), а при настроенном прокси строки прямого соединения (`dns`, `tls robots.txt`) стали информационными: прямой недоступ YouTube в этих условиях ожидаем и не означает сбой прокси.

Новые компьютерные тесты повторяют найденные ошибки: полная цепочка «демон → stdin дочернего процесса → запрос через прокси» для CONNECT и SOCKS5, разбор URL без глобального `URL`, конструктор настоящего yt-dlp из пакета с параметром прокси, строка `check` через прокси. Эти ошибки ловятся тестами до сборки.

## Настройка

Один файл на головном устройстве (по SSH, права root):

```sh
printf '{"url": "socks5://USER:PASS@HOST:PORT"}\n' > /var/opt/jap-ridetube-d/state/proxy.json
chmod 600 /var/opt/jap-ridetube-d/state/proxy.json
systemctl restart jap-ridetube-d.service
```

Схемы `http://` и `socks5://` (порт по умолчанию 8080/1080). DNS резолвится на стороне прокси; проверка аренды `mgu-uplink` при прокси пропускается. Учётные данные попадают к дочерним процессам через stdin и файл `cache/proxy.json` (0600, владелец — интернет-uid), не через argv/env. Удаление файла возвращает прямое соединение.

Проверка на машине (root):

```sh
/var/opt/mgu-python/current/bin/python3 /var/opt/jap-ridetube-d/current/ytfetch.py check \
  --cache-dir /var/opt/jap-ridetube-d/cache/ytfetch-check --proxy-file /var/opt/jap-ridetube-d/cache/proxy.json
```

Строка `proxy` должна быть PASS; `dns` и `tls robots.txt` при настроенном прокси могут быть INFO. Код входа, поиск и запуск видео проверяются на стоянке как раньше.

Ограничения: через прокси идёт весь трафик видео (при 720p ориентировочно 1–1,5 ГБ/ч на стороне прокси-сервера); публичный прокси-порт собирает сканирование — держите сложный пароль и fail2ban. Экран настройки прокси в самом приложении не входит в эту версию. Архивы 0.3.11 не заменяются и остаются в релизе для сравнения.
