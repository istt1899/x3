# MGU Video 0.4.5 — исправление запуска VK и зависания на 0 %

Версии: общая служба **0.4.5**, VK Видео/RUTUBE **0.1.6**. YouTube остаётся **0.3.16**.

В 0.4.4 внутренний дочерний загрузчик передавал отрицательный VK ID как аргумент
командной строки без разделителя. Идентификаторы роликов сообществ начинаются с
минуса; Python отклонял их до первого обращения к CDN. Исправлен именно этот
вложенный запуск. Также исправлен разбор перемежающихся опций и необязательных
позиционных аргументов в Python 3.12 на MGU; Python 3.13 на ПК маскировал этот
дефект. Оба входа загрузчиков и тёплый процесс проверяются с отрицательным ID.

Отдельно исправлена невидимая ошибка получения ссылки: раньше gateway передавал
сообщение об ошибке, а UI продолжал показывать локальное состояние «Подключаемся,
0 %». Теперь отказ переводит плеер в состояние ошибки с повторным запуском.
Получение ссылки ограничено 45 секундами, ожидание первых данных CDN — 25 секундами,
отсутствие дальнейшего прогресса — 35 секундами. DNS, TLS, HTTP 401/403/404 и таймаут
имеют безопасные понятные сообщения без подписанных адресов и токенов.

Добавлены этапы «Получаем ссылку на видео», «Подключаемся к серверу видео» и
«Получаем данные видео». Замер скорости в меню продолжает измерять отдельный
сервер и сам по себе не подтверждает загрузку конкретного ролика VK.

На ПК проверена гостевая цепочка настоящего VK: поиск похожего матча, получение
источника и первые данные CDN. Нормализатор получил пригодный аудиофрагмент
за 2,78 с после своего запуска; это результат сети ПК, не замер на автомобиле.
[Запись проверки](https://github.com/istt1899/x3/blob/main/media/validation/live-vk-start-0.4.5.json).

Точный архив 0.4.5 прошёл штатный install check и MP4/TS remux с закреплённым
FFmpeg на Linux. Проверки Python 3.12, Node 8, отрицательных ID, отказов и таймаутов
прошли: [GitHub Actions](https://github.com/istt1899/x3/actions/runs/42480669734),
[доказательство архива](https://github.com/istt1899/x3/blob/main/media/validation/linux-runtime-0.4.5.json).

## Обновление

MGU Store → **Настройки → Проверить**. Обновите **MGU Video service до 0.4.5**,
затем **VK Видео и RUTUBE до 0.1.6**. Если Store запросит перезапуск, выполните его.
Служба доступна и из прежнего источника `istt1899/ridetube`, приложения — из
`istt1899/x3`. Аккаунты сохраняются.

На стоянке проверьте тот же ролик, затем публичный ролик из поиска. При отказе
теперь должен отображаться текст причины. Звук продолжает работать в движении;
ограничение изображения на водительском экране сохраняется.
