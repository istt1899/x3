# Тестовая установка: VK Видео и RUTUBE

Это кандидат общего сервиса 0.4.0 и двух приложений 0.1.0. На автомобиле они ещё не
испытаны. Текущий стабильный источник `istt1899/x3` продолжает выдавать прежний
каталог; установка через обычный Check now пока не добавляет видео.

## Что получает владелец

Три отдельные плитки: прежний RideTube (YouTube), VK Видео и RUTUBE. Служба
`jap-ridetube-d` одна: приложения по очереди используют общий звук и декодер.
Поиск или открытие аккаунта второго сервиса не должны прерывать текущий звук.
Запуск другого видео останавливает предыдущее.

YouTube продолжает использовать уже настроенный `state/proxy.json`. Системный VPN
не устанавливается. VK и RUTUBE обращаются к своим серверам напрямую, в том числе
при наличии proxy.json и HTTP_PROXY. Интернет с iPhone остаётся источником сети;
VPN на iPhone не является механизмом маршрутизации этих приложений.

У VK доступны поиск и публичные видео. Настоящий вход требует собственного
зарегистрированного VK ID приложения, разрешений на Video API и HTTPS-посредника;
подробности в [инструкции посредника](auth-relay/README.md). Без настройки экран
аккаунта честно предлагает подключить VK ID. Пароль VK в MGU не вводится.

RUTUBE выдаёт QR/код для `rutube.ru/activate/`. Владелец подтверждает свой аккаунт
на телефоне. До этого поиск и главная работают в гостевом режиме. Подтверждение
личного аккаунта и его продление пока не проверены владельцем.

## Перед переводом в обычный каталог магазина

1. Проверить пакет на поддерживаемом ID7 MGU на стоянке. Установщик должен выполнить
   `service/check.sh`: синтаксис Node 8, наличие зависимостей, запуск именно
   поставленного Linux FFmpeg и автономный MP4/MPEG-TS → H.264/AAC тест. Неуспешную
   проверку нельзя обходить; она должна приводить к откату установки.
2. Настроить VK ID и HTTPS callback. Секрет `broker_key` хранится только на VPS и в
   приватном `state/vk/config.json` автомобиля с правами 0600. В архивы, каталог,
   QR, argv и публичный репозиторий он не включается.
3. Подтвердить вход обоих владельческих аккаунтов с телефона и проверить выход,
   повторный запуск службы, поиск, миниатюры, короткое и длинное видео, паузу,
   перемотку, смену качества и переключение между сервисами.
4. Проверить прежний YouTube и его прокси после обновления общей службы.
5. Опубликовать один и тот же проверенный сервис также в исходном источнике
   `istt1899/ridetube`: установленный компонент обновляется из своего origin.
   Один каталог x3 не гарантирует обновление уже установленной службы RideTube.
6. Объединить каталоги с сохранением «Кодировки • X3» и YouTube. Проверить оба
   источника: release `catalog/catalog.json` и raw `main/catalog.json`. Только
   после этого обычный Check now должен предлагать эти приложения.

## Приёмка на MGU

Проверка выполняется на стоянке. У новых приложений видео по умолчанию выключено
до определения состояния автомобиля; неизвестная скорость запрещает изображение.
Кодировки автомобиля приложение не меняет.

- Гостевой поиск VK и RUTUBE возвращает настоящие карточки и миниатюры.
- Ролик VK даёт звук через BMW MediaPlayer и изображение через mgu-render.
- Ролик RUTUBE HLS даёт оба потока, пауза и перемотка сохраняют синхронизацию.
- После 30 минут паузы/просмотра смена качества получает свежий медиаресурс.
- При сетевой ошибке вход не теряется; отозванный токен не считается действующим.
- При быстром Stop, смене качества и переключении сервиса остаётся один декодер.
- Поиск и вход другого сервиса не перехватывают звук.
- После закрытия/повторного открытия интерфейса состояния не смешиваются.
- Прежний RideTube входит, ищет, показывает картинки и воспроизводит через прокси.
- Ошибки установки и несовместимый runtime дают откат; рабочая версия остаётся.

Не публикуйте `account.json`, proxy.json, VK config.json или URL с паролем вместе с
результатами приёмки. Для анализа нужны версии пакетов и обезличенные ошибки.
