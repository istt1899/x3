# ТЗ: YouTube, VK Видео и RUTUBE на MGU

Начальное ТЗ сформировано до реализации по просьбе владельца. Репозиторий публикации — `istt1899/x3`; существующий компонент «Кодировки • X3» сохраняется.

## Приложения

- RideTube (`jap_ridetube`) — YouTube, существующая учётная запись и настроенный прокси.
- VK Видео (`marku_vk_video`) — самостоятельная плитка, прямой интернет, отдельная учётная запись.
- RUTUBE (`marku_rutube`) — самостоятельная плитка, прямой интернет, отдельная учётная запись.

Существующая служба `jap-ridetube-d` становится единственным общим проигрывателем: один аудиоисточник SOME/IP 1046 → 1024 и один `ytdec`. Три интерфейса управления, самостоятельные состояния авторизации, кеши и политика сети. Подключение/поиск другого приложения не перехватывают воспроизведение. Новое воспроизведение останавливает предыдущее; завершение старого запроса не меняет нового владельца.

## Функции

Поиск, карточки, миниатюры, выбор видео, запуск, пауза, перемотка, остановка. Русские подписи, управление iDrive и касанием. Сохраняются ограничения видео при движении; кодировки автомобиля не меняются.

RUTUBE: гостевая главная, вход через реальный телевизионный QR/код, персональные разделы только при действующей авторизации. VK: гостевой поиск и публичные видео; официальный VK ID вход требует app_id/redirect URI владельца, PKCE и подтверждения доступа к video API. Профиль VK ID не считается успешным доступом к VK Видео.

Авторизация не требует ввода пароля в машине. Неподдержанный или ненастроенный вход показывается явно; успешное состояние не имитируется. Владелец должен подтвердить связывание своего аккаунта на телефоне.

## Сеть и данные

VK/RUTUBE не наследуют proxy.json YouTube или HTTP_PROXY окружения. Учётные данные каждого сервиса хранятся отдельно, файлы 0600; каталоги 0700. Токены, cookie и PKCE verifier не уходят в UI, argv, публичный каталог или журналы. Публичный клиент TV при необходимости извлекается из актуального first-party приложения, как параметры YouTube TV.

## Медиа

У YouTube используется текущий путь. VK progressive MP4 и RUTUBE HLS требуют отдельной нормализации H.264/AAC: FFmpeg без перекодирования там, где исходник совместим, затем существующие MGYI/Annex-B и M4A для `ytdec`/BMW MediaPlayer. DRM не поддерживается. Если формат не подходит, приложение сообщает конкретную ошибку.

## Поставка

Новые приложения собираются без BMW SDK. SDK восстанавливает штатный установщик из donor на MGU; тестовый stub не выдаётся за SDK. Публичные архивы, лицензии, размер и SHA-256 проверяются. Общая служба должна быть доступна также в исходном `istt1899/ridetube`, поскольку Store обновляет уже установленный компонент из его origin. Каталоги объединяются с сохранением существующих компонентов.

## Приёмка

Реальные ответы поиска/метаданных, реальные коды входа, сохранение/выход аккаунта, Direct/Proxy изоляция, переключение владельца, неизвестные/просроченные callback, отключение сокета, форматы и перемотка. Node 8 проверяется настоящим процессом, не только современным Node. Компьютерные проверки отделены от испытания на автомобиле. До подтверждения на MGU выпуск обозначается кандидатом.

Открытые условия: app_id и redirect URI для VK ID, доступный HTTPS callback при выбранной схеме входа, подтверждение личных аккаунтов и проверка на автомобиле.
