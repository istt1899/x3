# VK Видео и RUTUBE: выпуск 0.4.1 для установки через Store

7 ноября 2026 года. Два отдельных приложения **0.1.1**, одна общая служба
**0.4.1**, прежнее приложение YouTube **0.3.13**. В каталоге сохранён актуальный
компонент «Кодировки X3» **0.1.2**, включая параллельно выпущенное исправление
импортов Store linker. [Инструкция скачивания](INSTALL-STORE-RU.md).

Это первый тестовый выпуск для автомобиля. Реальные интернет-запросы и Linux
проверены; воспроизведение на конкретном MGU и вход личным аккаунтом владельца
проверяются после установки. QR/pending не выдаются за завершённый вход.

## Вход с телефона

Оба приложения показывают настоящие коды и ссылки своего сервиса. Пароль в MGU
не вводится. QR строится локально; изображения QR от стороннего сервера не
загружаются.

Для стандартного VK больше не нужны собственные APP_ID, redirect или relay.
Исследован [официальный VK Видео TV](https://vkvideo.ru/landings/tv_instructions/index.html),
публичная identity установлена по официальному APK. Проверена цепочка без
`client_secret`, cookie и личного аккаунта:

1. `auth.getAnonymToken` — анонимная сессия публичного ТВ-клиента;
2. `auth.getAuthCode` с минимальными `video,offline` — настоящий шестизначный код
   и короткая HTTPS-ссылка `qr.vk.ru/ca?q=…`;
3. `auth.checkAuthCode` — ожидание подтверждения владельцем;
4. после одобрения — проверка пользователя и доступа к видео до `signed_in`.

Истечение кода нормализуется из серверного epoch; длинное значение `expires_in`
не трактуется как многолетний TTL. Закрытие, отказ, новый код и выход отменяют
старые попытки. Секретный hash опроса, анонимный и пользовательский токены остаются
в приватном состоянии. Собственный VK ID/PKCE relay сохранён как необязательный
режим для отдельно настроенного приложения.

Для RUTUBE сохранён проверенный device flow официального TV-клиента: QR/код,
интервал опроса, проверка профиля и обновление токенов. Реально подтверждены
выдача кода и pending; завершённый личный вход без владельца не выполнялся.

## Видео и аккаунт

Гостевой поиск и публичные видео доступны без входа. При проверенном VK-аккаунте
добавлены «Мои видео» через `video.get`, поиск через `video.search` и извлечение
реально выданных `files.mp4_*`. Если API не даёт нативный поток приватного видео,
приложение сообщает это явно: один web-player не считается готовым MP4.

Приватные подсказки API, ключи доступа и кэш аккаунта не передаются в UI.
У каждого подтверждённого VK-сеанса свой закрытый каталог кэша. Выход останавливает
его проигрыватель до очистки файлов, удаляет личные списки/миниатюры/позиции и
обрывает устаревшие запросы. Поиск или выход VK не останавливает YouTube/RUTUBE.

Единственный владелец проигрывания, ожидание выхода старого decoder, обновление
подписанных ссылок перед сменой качества и сохранение старого кэша при ошибке
resolve продолжают действовать. Новые приложения сохраняют строгую блокировку
картинки при движении и при неизвестной скорости. Кодировки автомобиля не меняются.

## Сеть и общая служба

YouTube использует прежние аккаунт и `state/proxy.json`. Эта установка не добавляет
системный VPN и не публикует прокси-пароли. VK/RUTUBE используют прямое соединение
и игнорируют прокси окружения. Сетевые процессы работают с выделенным интернет-UID.

Store обновляет установленную службу из её origin, поэтому один и тот же архив
0.4.1 размещается также в `istt1899/ridetube/catalog`. Новые приложения доступны
в `istt1899/x3/catalog`. Прежние архивы не подменяются, предыдущие каталоги сохраняются.
Версионные PNG исключают подмену картинки у старого выпуска.

## Проверки и их границы

Проверяются настоящим Node 8: gateway, авторизация bridge, выход из аккаунта,
отмена запросов, переключение владельца и модель UI. Python-тесты охватывают
провайдеры, TV-коды/expiry/status, личные API, сохранение refresh, прямую сеть,
подписанные URL, HLS и нормализацию MP4/MPEG-TS.

Опубликованный FFmpeg **реально выполнен на Linux**, а не только проверен как ELF:
[первый успешный запуск](https://github.com/istt1899/x3/actions/runs/42355172649).
Штатный `check.sh` прошёл с Python 3.12 и без внешних сетевых интерфейсов.
MP4 и MPEG-TS дали по пять кадров H.264 и более секунды AAC. Тот же ELF включён
в 0.4.1; проверка exact-архива нового выпуска сохраняется в материалах приёмки.

На MGU установка также выполняет автономный FFmpeg-тест. Его нельзя обходить;
ошибка должна остановить установку. Проверка Linux не доказывает работу
аппаратного декодера, BMW MediaPlayer или конкретной версии MGU.

Пакеты приложений собраны source-only, без BMW SDK и без SDK stub. Штатный Store
восстанавливает SDK из donor на устройстве. Исходники и лицензии RideTube сохранены;
FFmpeg сопровождается точным source bundle и лицензиями. Хэши, результаты и ссылки
на фактические проверки находятся в [RELEASE-EVIDENCE.json](RELEASE-EVIDENCE.json).

В сборщик кодировок добавлена защита: он откажется публиковать одиночный coding
каталог поверх общего каталога с видео. Это предотвращает потерю видеоприложений
при следующем отдельном обновлении «Кодировки X3».

## Приёмка владельцем

После установки на стоянке: QR-вход каждого сервиса → поиск → короткий ролик со
звуком → пауза/перемотка → смена качества → переход к другому сервису → выход и
повторный вход. Проверить прежний YouTube с настроенным прокси. Для разбора ошибки
достаточно версии службы и её текста; приватные JSON, токены и пароли присылать не нужно.
