Порядок публикации: source commit/push → два неизменяемых release с проверкой публичных SHA → catalog последним → root catalog commit/push → публичный reader Updater 0.8.18 через короткий источник → реальное HTTPS-обновление базы под Node 8. Результат публикации сохраняется отдельно от исходников; пункты после публикации не считаются выполненными лишь на основании этого плана.

## Доставка при HTTP 504 GitHub Releases

Первоначальные browser download URL GitHub возвращали 504 локально и в двух независимых облачных прогонах. Это не объявляется успешной проверкой установки: [прогон всех маршрутов](https://github.com/istt1899/bmw-kaluga-cameras/actions/runs/42465966209) отдельно подтвердил main/короткий каталог и отказ трёх browser-путей.

Те же архивы, значок и USB ZIP опубликованы в отдельной ветке store-artifacts-0.7.0, commit 64520258d0828946c18d8efb71115be8b430b8a6, с лицензией и ссылкой на исходный e98a5f9. В каталоге используются ссылки на точный commit, не изменяемая ветка. SHA/размер/name/version сверяются генератором с подготовленными файлами; неизвестный владелец, ветка вместо commit, query, credentials и несовпадение байтов отклоняются тестом test_release_downloads.js на Node 8/24.

Все четыре файла из закреплённого raw-зеркала скачаны неизменённым fetch.js Updater 0.8.18 под настоящим Node 8.17.0 без повторных попыток: приложение 130836, сервис 571792, значок 5118, USB 704432 байта. Все SHA совпали. После обновления каталога штатный короткий HTTPS-источник повторно проверен полным reader Updater 0.8.18 и его неизменённым fetch.js под Node 8: каталог, оба архива и SHA совпали, повторных запросов не понадобилось. Node 24 reader также прошёл. [Независимый облачный прогон HTTPS-источника](https://github.com/istt1899/bmw-kaluga-cameras/actions/runs/42466618409) завершён успешно: main/короткий источник и оба файла PASS. GitHub Releases browser-путь отдельно сохранил 504; он не используется этой HTTPS-проверкой и не объявляется исправленным.
