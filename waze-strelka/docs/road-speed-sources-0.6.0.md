# Источники дорожного ограничения скорости: проверка для 0.6.0

Проверено 07.11.2026. Ни один новый источник ниже не подключён к автомобилю или runtime. База камер, её версии и существующее покрытие **203/308** не изменены. Дорожный лимит текущего участка и лимит, подтверждённый для конкретной камеры, остаются разными фактами.

## Что доступно сейчас

- Готов модуль `alert-preferences.js`: дальность 50–1000 м с шагом 50, десять известных типов камер и «другие», частичные команды и миграция сохранённых настроек. Это управление предупреждениями, а не источник новых лимитов.
- Существующие подтверждённые данные и ссылки на OSM используются по прежним правилам. Неизвестные значения не заполняются городским значением по умолчанию.
- Модуль настроек и отдельные регрессии проверены на Node 24 и Node 8.17. Интеграция UI, persistence и guidance выполняется отдельно.

## Яндекс: официальный API существует, готового MGU-подключения нет

Официальный **NaviKit SDK** предоставляет `Guidance.getSpeedLimit()` — nullable `LocalizedValue` для текущей дороги. Вместе доступны `getLocation()`, `getRoadName()` и `getSpeedLimitStatus()`. Отсутствующий лимит должен оставаться неизвестным. `LocalizedValue.getValue()` использует SI: для скорости это м/с; перевод в км/ч требует множителя 3,6. Локализованный `getText()` не следует разбирать как машинное значение. [Guidance](https://yandex.ru/maps-api/docs/mapkit/com/yandex/mapkit/navigation/automotive/Guidance.html), [LocalizedValue](https://yandex.ru/maps-api/docs/mapkit/com/yandex/mapkit/LocalizedValue.html).

Важное ограничение: `UpcomingRoadEvent.getEffectiveSpeedLimit()` может подставлять стандартный городской лимит, когда у камеры собственного лимита нет. Это поле **не является доказательством лимита конкретной камеры** и не подходит для заполнения неизвестных записей нашей базы. [UpcomingRoadEvent](https://yandex.ru/maps-api/docs/mapkit/com/yandex/mapkit/navigation/automotive/UpcomingRoadEvent.html).

Доступ к NaviKit предоставляется по запросу; документированы Android и iOS, а прямой runtime Linux MGU/Node 8 среди платформ не указан. Технический следующий вариант — отдельное приложение на телефоне с документированным SDK и согласованной передачей свежего дорожного контекста в MGU. Это предложение архитектуры, а не уже доступная или разрешённая интеграция. [Платформы и доступ](https://yandex.ru/maps-api/docs/mapkit/index.html).

Стандартные условия ограничивают обработку/хранение результатов (§5.1.6) и показ результатов маршрутизации в сторонних приложениях и картах (§6.2.1). Поэтому право передавать данные в отдельное приложение и HUD необходимо отдельно согласовать с поставщиком; наличие API-ключа само по себе этого не подтверждает. Закрытые API, извлечение SDK-карт и скрейпинг не предлагаются. [Официальные условия, публикация 01.09.2026](https://yandex.ru/legal/maps_api/ru/).

В просмотренном описании ответа обычного HTTP Router API документированы геометрия, длина и время маршрута; функции выдачи действующего дорожного `maxspeed` там не найдено. Расчёт длина/время является оценкой движения, а не разрешённой скоростью. [Ответ Router API](https://yandex.ru/maps-api/docs/router-api/response.html). Отдельный продукт «Скоростной режим» существует у Яндекс Маршрутизации по запросу, но описан как анализ курьерских треков, а не общедоступный источник лимита для произвольной точки MGU. [Скоростной режим](https://yandex.ru/routing/doc/ru/extras/speed-limit).

## BMW: обнаруженные локальные контракты, статус not wired

Исследована только схема `public-m8-20-07-someip-interfaces.json`. Это схема другой известной версии системы, а не подтверждение наличия и семантики сигналов на конкретной машине. Чтение схемы не запускало подписки, кодирование, запись или управление автомобилем.

Нельзя считать каждое число актуальным разрешённым км/ч без проверки реального провайдера и согласованности двух событий. |

Единицы двух BMW-интерфейсов имеют **разные числовые коды**: `0` означает KMH в CCP и unknown во front-camera. Использовать общую таблицу декодирования нельзя.

## Следующий осуществимый шаг

Наиболее прямой локальный кандидат — проверка **CCP.effectiveSpeedLimit + speedLimitUnit**: только чтение на реальной версии провайдера, журнал полученных значений/единиц/времени получения и сопоставление со штатным SLI на известных участках и переходах лимита. До проверки sentinel/масштаба, доступности, потери сигнала и привязки к текущей дороге статус остаётся **not wired**. Сырые события front-camera можно рассматривать как исследовательскую диагностику, а не как готовый заменитель SLI.

Если этот путь недоступен, следующий продуктовый вариант — согласованный с Яндексом NaviKit-компаньон. В обоих случаях будущий контракт должен хранить источник, единицы, свежесть и состояние known/unknown; текущий дорожный лимит нельзя автоматически записывать как постоянный лимит соседней камеры.

Уже сейчас можно улучшать удобство настроек, устойчивость guidance и явное объяснение «лимит неизвестен». Обещание 308/308 без новых подтверждённых фактов технически не обосновано.
