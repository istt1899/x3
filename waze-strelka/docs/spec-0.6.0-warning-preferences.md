# ТЗ 0.6.0: дистанция, типы и непрерывность предупреждений

Совет: интерфейс MGU, алгоритм дорожного сопровождения, настройки и источники ограничений. Основание: дорожная проверка владельца после 0.5.2. Новый релиз приложения и сервиса — 0.6.0; база 2026.11.7.2 сохраняется, если проверенные данные не меняются.

## Настройки

На первой странице «Камеры», после переключателей выходов и до калибровки, размещается блок предупреждений. Дистанция: 50, 100, …, 950, 1000 м; по умолчанию 1000 м. Это дальность обнаружения по доступной дорожной геометрии либо по прямой для явно обозначенного режима «Рядом». Настройка не превращает близкую камеру в подтверждённую камеру вашей дороги.

Одиннадцать переключателей: скорость, средняя скорость, светофор, стоп-линия, ремень, пешеходный переход, полоса, телефон, знаки/разметка, расположение ТС/обгон и другие/неизвестный тип. Все включены при первой установке и миграции старых настроек. Если у комплекса несколько видов контроля, достаточно любого включённого. Описание сохраняет реальные сведения обо всех его видах контроля. При снятии всех галочек предупреждений нет; это состояние должно быть явно видно. Тест изображения остаётся отдельным стояночным тестом и не зависит от реального обнаружения.

Настройки хранятся вместе с прежними параметрами. Любая другая команда не сбрасывает дальность, фильтры, калибровку HUD/приборов или прозрачность. Интерфейс отображает только подтверждённое состояние сервиса. Недоступное хранилище обозначается как временное применение. Некорректная команда не изменяет ни один параметр. Прежний сервис без capability не получает неподдерживаемую команду.

## Сопровождение

В 0.5.2 каждый fresh-fix повторно требовал gain > 0,5 м между двумя отсчётами; активная камера не имела отдельного состояния сопровождения. Исправление разделяет первоначальное обнаружение и продолжение уже установленного подхода. Небольшие колебания расстояния и смена ближайшей диагностической точки не должны гасить подтверждённый подход.

На каждом отсчёте сохраняются проверки геометрии, принадлежности дороге и направления. Достоверность: UTC не старше 3 с, не более 500 мс в будущем, оценка точности не хуже 15 м. После проезда, ухода на другую дорогу/направление, истечения GPS, отключения предупреждений или несовпадения фильтров карточка снимается. Удерживать устаревшее расстояние либо переносить подтверждение на соседнюю дорогу нельзя. Изменение настроек применяется и при неизменном времени последнего GPS-отсчёта.

Первоначальное подтверждение движения и продолжение ранее подтверждённого подхода разделяются: замедление до 3–8 км/ч само по себе не снимает карточку, если геометрия и направление остаются пригодными. Новый GPS-отсчёт не создаётся повторным чтением прежнего UTC. Изменённая позиция того же UTC проверяется относительно исходной позиции этого временного отсчёта; цепочка небольших изменений не должна превращаться в необнаруженный большой скачок.

## Ограничение скорости

Различать лимит конкретной камеры, проверенную дорожную ссылку и текущее ограничение дороги. Наличие дорожного числа у Яндекса не означает наличия свободного публичного API для его использования другим приложением. Проверяются официальная документация провайдера и доступный read-only контракт BMW. Подключение, требующее ключа/договора или недоказанного native API, не выдаётся за работающую функцию. Справочное значение не создаёт подтверждения дороги и сигнала превышения по одной близости.

## Диагностика и приёмка

В отчёте сохраняются configured distance, enabled types, текущая камера и причина перехода/снятия. Приёмка: траектории 1000→500→200→0; шаги выбора дистанции; медленные/повторные отсчёты; небольшое колебание позиции; соседняя камера; подтверждённая и неподтверждённая дорога; поворот; проезд; потеря GPS; фильтр каждого типа и смешанного комплекса; все галочки сняты; изменение на том же GPS timestamp; перезапуск с сохранением; отказ записи; реальные IPC-команды и подтверждения UI.

Последнее смысловое изменение состояния и последнее снятие предупреждения не перезаписываются обычными ожиданием/повторением того же отсчёта. Для снятия по GPS сохраняется подробный код: отсутствующая позиция, превышение 15 м, устаревший/будущий UTC либо скачок. Тест обязан проверить сохранение этой причины после последующих тиков.

Проверки выполняются на Node 24 и официальном Node 8.17, штатными валидаторами пакетов и воспроизводимостью LF/CRLF. Автомобильная проверка проводится отдельно владельцем. После успешных проверок публикуются оба immutable пакета, затем каталог; проверяется загрузка через существующий короткий источник.
