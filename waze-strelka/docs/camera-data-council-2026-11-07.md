# Совет по источникам камер: Калуга и Калужская область

Проверено 7 ноября 2026 года. Три направления исследования: приложения и поставщики; официальные региональные публикации; открытые данные и архитектура обновления. Прямой поиск Яндекса вернул CAPTCHA, которую не обходили. Использованы доступные первоисточники и общий веб-поиск; это исследованный набор источников, а не утверждение о просмотре всего интернета.

## Решение

Для текущего публичного приложения основа — официальный перечень Госавтоинспекции, отдельный OSM-слой и явно помеченные сообщения владельца. Для более полного покрытия моделей, лимитов и направлений требуется согласованный профессиональный feed. Покупка обычного мобильного приложения сама по себе не предоставляет право опубликовать его базу на GitHub.

Найден [официальный XLSX по Калужской области](https://xn--80aebkobnwfcnsfk1e0h.xn--p1ai/upload/site40/report/publication/file/sayt_oktyabr.xlsx), опубликованный в разделе региона [01.10.2026](https://xn--80aebkobnwfcnsfk1e0h.xn--p1ai/r/40). SHA-256 исходника: `a62b2858aecdbeb63e43445b556c9db9d6c628e674c9e96fb5a5a01074d16089`. Условия воспроизведения в footer сайта МВД разрешают использование материалов с указанием первоисточника; это отдельное основание, не лицензия ODbL на официальный слой.

**308 записей не означает 308 разных физических камер.** Близкие координаты разных источников автоматически не склеиваются. Одна точка источника может описывать рубеж или направление контроля, а один комплекс — несколько направлений. Повторное наблюдение одного семейства данных не является независимым подтверждением.

По официальному перечню для Плеханова — Суворова и Генерала Попова — Тульское шоссе перечислены скорость, ремень/мотошлемы, красный сигнал, стоп-линия и требования знаков/разметки. Для четырёх рассмотренных OSM-объектов добавлена связь **с рубежом**, без подмены координат, индивидуальной модели, лимита или направления устройства. Связи проверены по адресу и расстоянию 1,9–15,9 м. Исходные 19 дорожных коридоров сохранены.

Болдина — Никитина по-прежнему остаётся сообщением владельца об ориентире: отсутствие в найденном перечне не доказывает отсутствие камеры. Неоднозначное «около Белого дома» не привязано к придуманной точке.

## Какие поля остаются неизвестными

Официальный XLSX не содержит числовых ограничений скорости, марки комплекса, азимута и подтверждённой фиксации «в лоб/сзади». Фраза «встречное/попутное» сохраняется как условие из перечня, без превращения в азимут или сторону фиксации. Общая категория знаков/разметки не переименовывается в контроль автобусной полосы; широкая категория расположения ТС/разъезда/обгона также сохраняет свой смысл.

В Speedcamonline курс означает направление движения автомобиля; в OSM `direction` для speed-camera описывает ориентацию камеры. Это разные семантики. Даже известная ориентация не доказывает сторону фиксации конкретного комплекса. Документация NaviKit также допускает стандартный городской лимит при отсутствии лимита камеры; такой fallback нельзя импортировать как измеренный факт.

## Механизм обновления

1. Отслеживать официальный региональный индекс и SHA исходного файла. OSM проверять отдельно по state/MD5, а изменение camera-фактов — по нормализованным данным внутри границы, а не по дате PBF.
2. Хранить исходник, дату публикации, дату получения, хеш, строки и исходные формулировки. У каждого поля сохранять источник и семантику; неизвестное не заполнять значением по умолчанию.
3. Создавать кандидата, отчёт изменений и очередь ошибок. Новые/удалённые позиции, географические выбросы, конфликты лимитов и изменение формата требуют рассмотрения.
4. Публиковать после проверки неизменяемый data artifact с размером/SHA и только затем manifest. Данные обновляются отдельно от программы. Канал `manifest-v2.json` отделён от старого OSM-канала для совместимости клиентов 0.4.x.
5. На MGU атомарно активировать проверенную базу, сохранять предыдущую и показывать результат. Более новая база из пакета также должна применяться офлайн; явно выбранный откат сохраняется после перезапуска.
6. Рекомендуемый режим эксплуатации: серверная проверка источников ежедневно, публикация только после проверки изменений. Для автомобиля — проверка небольшого manifest при доступном интернете и ручная кнопка. Автоматический ежедневный опрос на машине — отдельная пользовательская настройка, не скрыто включённая функция текущего релиза.

Host-инструмент проверки создаёт отчёт и кандидата, но не публикует непроверенные сведения. В GitHub предусмотрен ручной workflow; расписание не активируется молча. Полноту всего региона нельзя подтвердить одним списком: остаются новые установки, временные средства, устаревшие записи и ошибки источников. Запрос профессиональному поставщику должен отдельно требовать RU-KLU, направления контроля, типы, лимиты, историю изменений и права на публичное распространение.
